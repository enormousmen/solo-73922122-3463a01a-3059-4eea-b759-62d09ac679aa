# 单卷恢复控制台(volume-recovery)

虚拟机数据盘尚未恢复完,值班员需要立刻恢复业务读写。本服务提供单卷恢复页:

- **4 KiB 块读写**:本地块用 SQLite 持久化(`<DATA_DIR>/volume.db`);本地缺块时从**内置只读备份镜像**读透;
- **后台回填**:网页一键启动,后台线程把缺块从备份拷贝到本地,页面实时显示进度;
- **范围清零**:值班员输入起止块号,范围内**本地块与缺块一起清零**——删除本地块释放空间
  供后续写入复用,范围以**紧凑区间标记**持久化(重叠/相邻自动合并,不逐块建记录);
  清零后新发起的读返回全零,后台回填跳过清零块,**在途回填数据也不写回**;
  清零与业务整块写入重叠时**以最后提交的操作为准**;清零块**计入恢复进度(每块只算一次)**;
  整个清零操作是单个事务,**失败时数据与进度维持原状**;
- **按块挂起/放行**:网页可挂起指定块的后台备份读取;挂起期间同一块的**整块写入照常提交**,
  迟到的备份数据(`INSERT OR IGNORE` + 落盘前复查挂起表)**不会覆盖**已提交的业务写入;
- **重启续传**:已落盘的块与清零标记保存在 SQLite 中,进程重启后保留,且未完成的回填**自动继续**;
- **断开保护**:只要还有缺块就**拒绝断开备份**(HTTP 409);补齐(回填+清零)后允许断开,
  断开后数据盘纯本地读写(清零块仍读全零)。

## 目录结构

```
app/
  app.py               # Flask 服务:存储层(Volume)+ 回填 worker + 清零 + REST API + 页面
  backup_util.py       # 只读备份镜像生成器(内容确定性,可由块号推导)
  templates/index.html # 单页控制台:状态卡、块网格、块操作、范围清零、两键演示脚本
  requirements.txt     # flask
  Dockerfile           # 构建期生成 /app/backup.img 并 chmod 0444(内置只读镜像)
tests/
  test_recovery.py     # pytest 自测(15 项)
docker-compose.yml     # 一键启动:8080 -> 5000,命名卷 recovery-data 持久化 /data
```

## 运行

### Docker Compose(交付方式)

```bash
docker compose up --build
# 打开 http://localhost:8080
```

- 容器内 `/app/backup.img` 为构建期生成的只读备份镜像(256 块 × 4 KiB = 1 MiB);
- 本地块存于命名卷 `recovery-data` 中的 SQLite,`docker compose restart` 后保留并自动续传。

### 本地直跑(开发/自测)

```bash
pip install -r app/requirements.txt
python3 app/app.py          # http://localhost:5000
```

可用环境变量:`BLOCK_SIZE`(默认 4096)、`BLOCK_COUNT`(默认 256)、`BACKFILL_DELAY`(默认 0.05s/块)、
`DATA_DIR`、`BACKUP_IMAGE`、`PORT`。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 总块数/已落盘/已清零/缺失/进度/清零区间/回填与备份状态/统计 |
| GET | `/api/blocks` | 已落盘块及来源、挂起列表、清零区间 |
| GET | `/api/block/<i>` | 读块:本地命中 / 清零块全零 / 缺块读透备份 / 挂起 409 / 断开且缺失 410 |
| POST | `/api/block/<i>/write` | 整块写入(`{"data": "..."}`,UTF-8 ≤ 4096 B,补 0 凑整块;写入会把该块移出清零区间) |
| POST | `/api/block/<i>/suspend` · `/resume` | 挂起 / 放行该块的后台备份读取 |
| POST | `/api/zero` | 范围清零(`{"start": s, "end": e}`,闭区间;非法范围 400 且状态不变;失败整体回滚) |
| POST | `/api/backfill/start` | 启动后台回填(已断开备份则 409) |
| POST | `/api/disconnect` | 断开备份:有缺块则 409 拒绝,补齐(含清零)后断开成功 |
| POST | `/api/reset` | 清空本地卷(含清零标记,演示用) |

## 关键设计

- **清零语义**:清零范围落库为 `zero_ranges(start, end)` 闭区间表——重叠/相邻区间自动合并,
  一个连续范围只占一条记录;清零在同一事务内删除范围内本地块(释放本地空间)、清除范围内挂起、
  合并写入区间标记,任一步失败整体回滚,数据与恢复进度维持原状。
- **清零与写入的先后**:本地块表与清零区间表永远互斥——清零删除范围内本地块,
  业务整块写入把该块从清零区间中移除(区间收缩/分裂);两者重叠时**以最后提交的操作为准**,
  恢复进度中每块只算一次(进度 = 已落盘 + 已清零,不会重复计数)。
- **清零后的读与回填**:读路径先查本地、再查清零(返回全零,不读备份);回填 worker 选块时
  跳过清零块,落盘前再复查清零表——取数后目标块被清零的在途备份数据直接丢弃(统计 `zero_dropped`)。
- **迟到备份数据不覆盖业务写入**:回填落盘用 `INSERT OR IGNORE`;从备份取数到落盘之间的窗口内
  若业务写入已提交,回填结果被丢弃(统计 `late_ignored`);落盘前还会复查挂起表,取数后被挂起的块直接丢弃。
- **挂起语义**:挂起只影响*后台*备份读取——回填 worker 跳过被挂起的块;缺块且被挂起时业务读返回 409;
  整块写入不受挂起影响,永远可提交。
- **持久化**:块、挂起表、清零区间、回填运行标志、断开标志全部在 SQLite(WAL);重启后按标志自动续传。
- **断开条件**:`missing > 0` 时断开返回 409(清零块不算缺块);断开后关闭备份 fd,读写在纯本地完成。

## 自测情况(已执行)

- **pytest 15 项全部通过**(`python3 -m pytest tests/ -v`,Python 3.11 + Flask 3.1):
  缺块读透且不落盘、回填至完成、挂起期间读拒/写可提交/放行后业务数据不被覆盖、
  缺块拒绝断开+补齐后断开+断开后可读写、跨重启保留块并自动续传、写入校验(超 4 KiB 400/越界 404)、
  回填并发业务写入不被覆盖;
  清零新增 8 项:紧凑区间合并且每块只算一次、清零释放本地空间且计入进度、
  清零与写入重叠以最后提交为准、清零块补齐后允许断开、在途回填不写回已清零块(连跑 5 次稳定)、
  非法清零 400 且数据与进度不变、清零标记跨重启保留+重置清除、清零清除范围内挂起。
- **真实 HTTP 冒烟**(独立进程 + curl/node,64/256 块卷):清零混合范围(已回填块+缺块)→
  读全零 → 清零后重写 → 非法清零 400 状态不变 → 回填跳过清零块至完成 →
  断开备份 → 断开后清零块全零/重写块可读;在途场景实测 `zero_dropped=1`;
  第二实例接管同一数据目录,清零区间、断开标志、业务数据全部保留,重置后清零标记清除。
- **演示二脚本端到端**(node 驱动 256 块卷,与页面按钮同一 API 序列):10 项断言全部通过
  (清零→全零→重写→回填完成 249+7=256→断开→断开后全零/可读)。
- **重启持久化**:本环境沙箱禁止 `kill` 信号,无法杀进程;改用等价验证——
  ① pytest 中 `vol.stop()` 后用同一数据目录创建全新应用实例(全新进程对持久层所见即如此),断言保留与续传;
  ② 回填中途/清零后用第二个服务实例接管同一数据目录,实测 `resumed_on_boot=true`、
  回填自动继续、清零区间与重启前业务写入保留。
- **compose 配置**:本环境无 Docker,未实际构建镜像;已用 PyYAML 校验 `docker-compose.yml` 语法与关键字段,
